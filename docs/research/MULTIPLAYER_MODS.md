# Multiplayer mods for single-player games: what to learn for DS2

Researched 2026-10-03 from public sources only (GitHub source read from shallow clones, wikis, docs). DD2gether and RE4R are in `docs/FINDINGS.md` and are not repeated here. Confidence tags: **[src]** = read in source, **[doc]** = official docs/wiki, **[sec]** = secondary/press/forum summary, **[low]** = thin or likely auto-generated documentation; treat as a lead only. Licences matter: GPL/AGPL code (Nitrox GPLv3, SkyMP GPLv3/AGPLv3, TiltedEvolution GPLv3, CyberpunkMP Tilted licence) is read-for-ideas only; copy nothing into this repo.

## 2. Findings by topic

### 2.1 Authority and ownership
- **Three working models.** (a) One authoritative server/host with clients sending intent (SkyMP, Nitrox server side, cyber.rest, Kenshi claims). (b) Per-object owner that simulates and reports (Valheim zones, FiveM scope, TiltedEvolution actors, Nitrox simulation locks, BeamMP vehicles). (c) The vanilla engine's own host/guest (Stardew, Seamless). DS2's "host is the world server, guest actions become host-confirmed changes" is (a) with owner-simulated vehicles, which matches what works.
- **Ownership needs an epoch.** TiltedEvolution's `OwnerComponent` carries `OwnershipEpoch`; every owner-originated message and release must present the current epoch or is ignored, and a rejected/unloaded candidate goes on `InvalidOwners` so ownership cannot bounce between clients that cannot load the actor. Kenshi's later authority doc independently adds `generation` + `LocalOwned/RemoteOwned/ServerOwned/PendingSpawn/Destroyed` states and echo suppression. Same shape twice.
- **Locks, not just owners.** Nitrox distinguishes EXCLUSIVE (piloting) from TRANSIENT (still simulating, anyone may steal with exclusive). DS2 equivalent: a driver takes exclusive on the vehicle and its load; when they exit the host takes it back transiently.
- **Hand ownership off on area unload and disconnect.** Nitrox revokes on cell leave and `RevokeAllForOwner` on disconnect; Tilted transfers on cell change and unavailable owner; FiveM warns never to cache owner.
- **Whitelist what is simulated.** Nitrox keeps an explicit `SimulationWhitelist` of creature types worth simulating instead of every entity the server spawned (stationary junk is skipped).
- **Server-owned beats weakest-client-owned.** Valheim's vanilla "first player owns the zone" lets the worst PC set simulation quality; server-owned zone mods exist to fix that. For DS2 with a fast host, simulating all enemies on the host is the right default.
- **Client-authoritative has a price.** BeamMP: each client simulates its own vehicle, so remotes jitter, snap or clip when packets are lost. Acceptable only for single objects like the driver's vehicle, with corrections.

### 2.2 Interest management
- Zone/cell based everywhere: Nitrox absolute entity cells (server decides sim per player per cell), SkyMP grid with neighbours, Kenshi 750 m zones 3x3, Valheim 5x5 active, FiveM culling radius. In all of them the server tells a client only about things near it, and ownership/simulation follows the same grid.
- Gotchas: Valheim creature caps counted across all loaded zones (split groups multiply load); FiveM reduced culling creates ownership issues because the owner is not known to every remote; Tilted needs a spawn request carrying the epoch so a late client does not instantiate stale owner state.

### 2.3 Remote players in engine
- Four patterns: (1) spawn an existing NPC/actor record and control it (CyberpunkMP Muppet record, DD2gether, SkyMP/Tilted actors, our DS2 borrowed NPC); (2) construct a body object and attach the game's animation controller, setting its parameter names directly (Nitrox `AnimationController["in_seamoth"]`, velocity-driven locomotion, `RigidBody.interpolation`); (3) reuse the game's own phantom/summon mechanism (Souls seamless, Seamless Co-op); (4) replay the factory call in place (Kenshi).
- **Drive locomotion, do not warp.** Nitrox sets `AnimationController.Velocity` from the corrected position delta each fixed step; cyber.rest issues AI move commands so the NPC animates instead of sliding; DD2gether sets speed to drive native locomotion. Warping alone slides. This is directly the DS2 animation mirroring problem (roadmap item 6).
- **Vehicles are tagged, non-persisted spawns with a named seat slot.** CyberpunkMP spawns vehicles with a tag, waits for the "Entity/Attached" callback (`OnVehicleReady`), then mounts the passenger to a seat slot by name; the author tried both direct `MountEntityToSlot` and "walk to the car". The "wait for attach, then mount" order is the non-obvious part; DS2 seating failures likely come from mounting before the entity is ready.
- **Tag and exclude puppets from persistence.** `persistState=false, persistSpawn=false, tags=[Puppet]` lets the game save and streaming systems ignore them and lets mods find them again. DS2 equivalent: ensure puppets never enter save data or mission systems.
- **Spawn throttling.** Kenshi caps spawns per player and retries; cyber.rest has a spawn/streaming manager that ground-snaps remote puppets until terrain is loaded (otherwise they fall through the map).

### 2.4 Animation sync
- Cheapest robust design is "send state, let the local animation system play it": velocity plus a few boolean parameters (Nitrox), action name replay plus motion bank/frame correction (DD2gether), animation layers (RE4R). SkyMP sends animation events with its own `AnimationSystem` and a blocked-animation list on the client. TiltedEvolution accepts custom animation mods via a separate sync add-on (`README-ANIMATION-MODS.md`, AnimSync Together), meaning unknown animations fail to sync unless explicitly listed.
- Lesson: whitelist animations/states you can reproduce (as Nitrox does with named parameters per vehicle type) and degrade to locomotion for the rest.

### 2.5 AI, enemies, damage
- **Hits are intents, results come from the owner.** SkyMP's `OnHit` carries aggressor, target, source weapon, flags (bash/power/sneak/blocked), projectile; the server applies an `IDamageFormula`. DD2gether's damage descriptors are the same. Tilted: "enemies not dying after hitting 0 HP" was a release bug, so deaths must be an explicit event, not inferred from HP.
- **AI hosting by clients is a first-class concept in SkyMP** (`hosters` map: server rejects position updates for an actor from anyone who is not its hoster, and tells other listeners `isHostedByOther`). That is the same as our "host simulates, others puppet" but with a per-actor hoster.
- **Scale difficulty with player count** (Seamless: +25/50/75 percent enemy HP for 1/2/3 partners).
- Kenshi docs (low confidence) admit NPC AI runs independently per client; this is the failure that host-authoritative enemies exist to avoid.

### 2.6 World state, quests, saves
- **One owner for story state.** Tilted: party leader's world is truth; members can fight and explore but quest dialogue, scripted events and quest-critical loot belong to the leader; changing leader mid-run breaks quests. Seamless: event flags sync to host, rewards for guests can be lost, fixed with an external save manager that repairs flags. Fallout Together: quest sync is the weakest feature. All three match DS2's "host owns orders" decision; none solved quest ownership for the guest cleanly.
- **Flag drift is the dominant bug class.** Seamless's own docs list flag ids to toggle by hand (e.g. Erdtree state inherited from invasions). Treat flags with echo suppression, one writer, and a repair tool/command.
- **Per-stage quest messages.** Tilted sends `RequestQuestUpdate{Id, Stage, Status}` from a player and the server validates against that player's quest log before notifying the party, ignoring "none/misc" quest types unless an experimental flag is on. Whitelist which quest types sync.
- **Saves.** Seamless uses its own save files per player. Kenshi: separate saves. cyber.rest: host-side JSON/SQLite store with GUID identity. SkyMP: server DB with change-forms. Our per-profile redirect plus host-to-guest save copy is in line; the SkyMP "change form" idea (store only deltas from the base game) is the only different approach.
- **Time/weather** are cheap global state; Hogwarts MP and Kenshi sync them at the framework level.

### 2.7 Desync detection and recovery
- Mostly absent by design. What exists: Nitrox NTP-corrected clock delta; Tilted epoch checks that drop stale messages; Kenshi echo suppression, stale-generation reject, pending-snapshot queue flushed on spawn; Valheim revisions per ZDO; Seamless relies on a manual repair tool. Nobody does periodic full-state hashing for a single-player engine; recovery is "re-snapshot the entity on demand" or "leave and rejoin".
- Pending-snapshot queue (Kenshi): updates for an entity that has not spawned yet are held and applied on spawn, expiring after 10 s. Cheap fix for join/stream races.
- Nitrox PR #2873: remote entities appeared once at (0,0,0) on first sync because ownership assignment and initial position arrived out of order. Always send position with spawn/ownership change.

### 2.8 Handling "the engine assumes one player"
- Block the engine paths that would act on the wrong player instead of rewriting them: SkyMP disables fast travel, difficulty selection, skill advance, blocks Papyrus events, runs a world-cleaner that despawns leftover actors, enforces limitations. Tilted disables buttons for non-leaders. DS2 already does this with the "guest gate".
- Leave the engine to do the transitions (Seamless patches the game's own session/co-op code so area transitions need no screen).
- Put UI perspective changes under control: Stardew swaps whole game state for split-screen via `PerScreen<T>`; most mods avoid it.

### 2.9 Transport and NAT
- Valve GameNetworkingSockets/Steam P2P is the common choice for no-server friends play (Seamless, cyber.rest with ICE + relay, DS seamless). LiteNetLib (Nitrox), ENet (Kenshi), RakNet-style UDP (SkyMP, BeamMP) elsewhere. Our ISteamNetworkingMessages choice matches the strongest low-friction option; nobody gets by without a relay fallback.
- Run networking off the game thread and marshal results onto it (cyber.rest golden rule; DD2gether fixed-step accumulator).
- Binary protocol: CyberpunkMP generates it with protobuf plus auto-RPC; Nitrox has one processor class per packet type, client and server. Tiny numbers of message types can still use a hand-rolled registry.

### 2.10 Tooling and workflow
- Script hosts: SkyrimPlatform (TypeScript in-process, hot reload), RED4ext + redscript + Codeware, UE4SS/Blueprints (Hogwarts), Harmony (Nitrox, Bannerlord), Ogre plugin loader (Kenshi), REFramework Lua. All of them give a way to hot-reload or script without restarting the game; that was the main productivity lever.
- Tests: SkyMP ran in-game unit tests with coverage in an experimental branch; Nitrox ships `Nitrox.Test` unit tests for packets/server logic separated from game code (`NitroxModel` has no game references so the server is testable). Kenshi has TestClient, IntegrationTest, LiveTest projects; Tilted has server unit tests and a Linux Docker server. Pattern: keep protocol + authority logic game-free so it runs headless with fake clients, which is what `tools/ds2/fake_peer.py` / `fake_launcher.py` already do.
- Admin/debug: Nitrox `PlayerCommand`/`QueryCommand` server commands; Tilted ImGui debug service; SkyMP console commands. A server-side "query entity owner / force transfer / re-snapshot" command is common.

### 2.11 Known failure modes (recurring)
1. Flag/quest drift between host and guest (Seamless, Tilted, Fallout Together).
2. Ownership bounce or lost owner when an actor unloads (Tilted `InvalidOwners`, FiveM owner caching).
3. Puppets falling through unloaded terrain or appearing at the origin on first sync (cyber.rest ground snap, Nitrox #2873).
4. Spawning through a path the engine does not expect crashes after a while (Kenshi direct spawn "destabilizes after 10 to 20 seconds").
5. Jitter/clipping when a client owns a moving object and packets drop (BeamMP).
6. Leader/host change mid-run corrupting quest progress (Tilted).
7. Performance scaling with synced object count, not map size (Valheim ZDOs).
8. Mod-dependent animations not syncing (Tilted AnimSync add-on).
9. Port effort is per-game and large (Starfield Together abandoned at ~70 percent; Souls per-game RE).

## 3. What DS2 should adopt (ranked)

| # | Recommendation | Source precedent | DS2 problem | Concrete change |
|---|---|---|---|---|
| 1 | **Ownership epoch + invalid-owner list on every host-owned or driver-owned object** (enemy, vehicle, dropped cargo, structure). Messages carry `(id, epoch)`; stale ones dropped; a candidate that cannot load the entity is excluded. | TiltedEvolution `OwnerComponent`, Kenshi generation ids | Enemy authority and puppets; vehicle driver ownership; desync recovery | Add `epoch` to host entity ids in the contract; reuse for VEHICLE_STATE and enemy_state; log rejects. |
| 2 | **Pending-snapshot queue**: hold position/state for entities not yet spawned, flush on spawn, expire at ~10 s; always send position with the spawn/ownership message. | Kenshi pending queue, Nitrox PR #2873 | Streaming and area transitions; partner at (0,0,0) | Queue in the adapter keyed by entity id; applies to cargo drops "placed once the receiver is near" too. |
| 3 | **Spawn/streaming manager for the partner body**: ground-snap until terrain under the puppet is loaded, spawn cap and retry, hide until ready, tag puppets and exclude them from persistence. | cyber.rest spawn manager, CyberpunkMP tagged non-persistent puppets, Kenshi spawn cap | Streaming and area transitions; puppets; save handling | Roadmap item 5: puppet spawn spec = non-persistent, tagged; wait for entity-attached before mount; ground raycast before show. |
| 4 | **Seat by "wait for ready, then mount to a named slot"** and keep the vehicle kinematic for the passenger. | CyberpunkMP VehicleSystem (Entity/Attached, slot name) | Reliable vehicle seating (roadmap item 1, 4) | Mount only after the vehicle entity reports attached; fall back to the "walk to the seat" path if a direct mount fails; test with the five enter/exit cycles in the roadmap. |
| 5 | **Drive locomotion from velocity and a whitelist of named animation parameters; degrade to walk/idle for unknown states.** | Nitrox AnimationController, cyber.rest AI move, DD2gether speed | Animation mirroring (items 6, 6b) | Send velocity + a small enum of states; whitelist per state with fallback; never warp alone. |
| 6 | **Quest/order ownership = host only, per-stage messages, type whitelist, and a one-writer rule for flags with echo suppression.** Guest may fight, loot non-quest items and use terminals; quest-critical interactions refused with a toast. | Tilted leader rules and QuestService, Seamless flags | Order and quest ownership (item 2, 9) | Keep the gate; add a "flag/fact diff" channel host to guest only; never allow host change mid-run (document it). |

| 8 | **Simulation whitelist + interest cells** for enemy and object sync: sync only archetypes that move or matter (MULEs, BTs, bandits, vehicles, dropped cargo), by area cell around each player; revoke on cell leave and on disconnect. | Nitrox `SimulationWhitelist` and per-cell sim, Kenshi 3x3 zones, SkyMP grid | Enemy authority bandwidth; structures (static ones not simulated); world-state sync | Use DS2's own streaming cells for the grid; static structures sync as create/destroy facts, not per-frame. |
| 9 | **Treat structures and roads as persistent facts (create/destroy/damage deltas), not simulated entities**; guest requests, host confirms. | 10 | **Join-time full snapshot plus on-demand re-snapshot command** as the only desync recovery; add a "resync entity/world" debug command on both sides. | Seamless repair tool, Nitrox InitialSync processors, Kenshi snapshot | Desync recovery; rejoin (item 9) | Per-subsystem `snapshot()` already needed for rejoin; expose via F-key/console; log divergence when a host-confirmed change is rejected. |
| 11 | **Keep protocol and authority logic game-free and runnable headless** (Nitrox `NitroxModel` vs patcher split; Kenshi test clients) and extend `fake_peer.py` into scripted multi-actor scenarios with recorded traces. | Nitrox.Test, Kenshi TestClient/IntegrationTest, SkyMP in-game tests | Two-PC testing harness | Add recorded-trace replay from a real two-PC run (both adapter logs) as a regression fixture; assert epochs/ownership transitions. |

### Explicitly not recommended
- Replacing the game's network or session system (Seamless can; it patches an existing co-op feature, DS2 has none comparable that is local-friendly; DS2 has online strand features that are risky).
- Direct memory-spawn of characters outside the game's own spawn path (Kenshi's fallback crashed after 10 to 20 s); prefer the game's spawn setup/encounter path.
- Full-state hashing for desync detection; nobody ships it for single-player engines, and the cost is high versus on-demand re-snapshot.
